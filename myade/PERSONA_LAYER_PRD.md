# 개인 ADE(myade) — 페르소나 레이어 추가 요청

> **상태: 완료 (2026-08-17)** — 아래 "완료 기준" 체크리스트 전부 충족 확인됨. 트러블슈팅 중 겪은 시행착오는 [`TROUBLESHOOTING.md`](./TROUBLESHOOTING.md) 참고.

> **선행 문서**: 배경/원 스펙은 [`ADE PROJECT.md`](./ADE%20PROJECT.md), 현재 상태는 [`README.md`](./README.md), 아키텍처 요약은 [`CLAUDE.md`](./CLAUDE.md) 참고. 이 문서는 그 위에 얹는 **새 단계(페르소나 레이어)**의 스펙이다.

## 배경

myade 1단계(세션 상태 조회 MCP 서버)는 완료되었고, 2단계(Tauri GUI 셸)는 개발 모드로 진행 중이다. 지금까지는 "여러 세션이 서로를 인지하는 것"과 "쓰기/삭제 명령을 안전하게 승인받는 것"에 집중했고, **세션이 끝나도 아무것도 기억하지 않는다** — 매번 새 대화처럼 시작한다.

이번 단계는 가벼운 방식으로 "이어지는 감각"을 더한다: 세션이 끝날 때마다 배운 것을 파일에 누적하고, 다음 세션 시작 시 그걸 읽어들이게 한다. Letta 같은 상태 기반 메모리 프레임워크의 정식 구현이 아니라, 그 방향으로 가는 **가장 가벼운 첫 걸음(파일 기반 "가짜 메모리")**이다.

## 이번 단계의 목표 (MVP)

- 세션 종료 시 Claude가 그 세션에서 파악한 사용자 선호(말투, 반복되는 요청 패턴 등)를 짧게 요약해 `persona.md`에 append한다.
- 새 세션 시작 시 `persona.md`의 누적 내용을 어떤 형태로든 그 세션의 컨텍스트에 반영한다 (구체적 방식은 "열린 기술 질문" 참고).
- 기존 1단계 서버(`SessionStore`, 훅 엔드포인트)를 그대로 재사용하고, 새 코드는 최소한으로 얹는다.

## 명시적으로 하지 않을 것 (스코프 아웃)

다음은 이번 단계에서 만들지 않는다. 아래 "다음 단계 (문서화만)" 섹션에 방향성만 남겨둔다.

- **멀티 pane 대시보드** — 여러 pane을 한 화면에서 동시에 보여주는 구조. 이번엔 만들지 않는다.
- **git worktree 자동 격리** — 여전히 스코프 아웃 상태 유지.
- **2단계(Tauri GUI) 자체의 변경** — 스택 재검토(웹 대시보드 전환 등) 논의는 있었으나, 이번 라운드에서는 Tauri를 그대로 유지하고 페르소나 레이어와 무관하게 둔다. GUI 코드는 건드리지 않는다.
- **방법 B (Letta 서버 연동)** — 상태 기반 메모리 프레임워크 연동은 이번 스코프가 아니다.
- **코드 컨벤션/실수 패턴 등 폭넓은 내용 기록** — 이번엔 말투/선호 톤 위주로 좁게 유지한다.

## 확정된 결정 사항

| 항목 | 결정 |
|---|---|
| 저장 위치 | 프로젝트별이 아닌 **전역 파일 하나** (`persona.md`, 위치는 구현 시 `data/` 옆 또는 사용자 홈 하위로 확정) |
| 내용 범위 | 말투/톤/선호 위주로 좁게. 코드 스타일·반복 실수 패턴 등은 다음 라운드로 미룸 |
| 요약 트리거 | **세션 종료(`Stop` 훅) 시 자동** — Claude 자신이 그 세션의 마지막 턴에서 한두 줄로 요약해 append |
| 옵트아웃 | 소프트 옵트아웃 지원 — 요약할 내용이 사소하면 건너뛰어도 된다는 걸 프롬프트에 명시 (매 세션 강제 append로 인한 노이즈 방지) |
| 기존 코드 통합 | 새 로직은 1단계 서버(`register.js`/훅 핸들러) 근처에 얹는다. 별도 프로젝트로 분리하지 않는다 |

## 열린 기술 질문 (구현 전 확인 필요)

- Claude Code의 `SessionStart` 훅이 **컨텍스트 텍스트를 직접 세션에 주입**할 수 있는지, 아니면 MCP 리소스/도구 응답으로만 노출 가능한지 확인 필요. 이에 따라 주입 방식이 달라진다:
  - (a) 가능하다면 → 훅 응답에 `persona.md` 내용을 실어 전달
  - (b) 불가능하다면 → MCP 도구(`persona_get` 등)를 새로 만들어 세션 시작 시 Claude가 스스로 호출하게 유도, 또는 `CLAUDE.md` 앞에 자동으로 prepend하는 스크립트 방식 검토

## 완료 기준 (Acceptance Criteria)

- [x] 세션 하나를 정상적으로 마치면 `persona.md`에 그 세션 요약이 한두 줄 추가된다. (`src/persona.ts`의 `onSessionEnd`/`appendPersonaLine`)
- [x] 사소한 세션(예: 단순 질의응답)에서는 옵트아웃되어 `persona.md`가 불필요하게 늘어나지 않는다. (`SKIP` 응답 처리 + 형식 미준수 시 폐기)
- [x] 새 세션을 시작했을 때, 이전 세션에서 기록된 말투/선호가 실제로 반영된 응답을 확인할 수 있다 (예: "반말로 해줘"가 기록되어 있으면 다음 세션에서 반말로 시작). 실제로 이번 세션에서 `SessionStart` additionalContext로 기록된 말투 선호가 주입되고 반영된 것을 확인함.
- [x] 기존 1단계 기능(`pane_list`/`pane_status`/`pane_ping`, 세션 인지)은 이번 변경으로 영향받지 않는다. 오늘 `pane_list` 직접 호출로 확인함.
- [x] 2단계(`myade-gui`)는 이번 변경 대상이 아니며 코드 변경 없음.

## 다음 단계 (Future Scope — 문서화만, 이번 라운드 대상 아님)

- **멀티 pane 대시보드**: 여러 세션을 한 화면에서 동시에 보고, 상태/작업 내용을 한눈에 확인할 수 있는 뷰. Tauri 앱 위에 얹을지, 별도 레이어로 뺄지는 그때 재논의.
- **git worktree 자동 격리**: 세션(pane)마다 별도 브랜치를 자동 할당하는 기능.
- **2단계 GUI 스택 재검토**: Tauri 유지 vs 웹 대시보드 전환 여부. 이번엔 결론 내리지 않고 유지하기로 했으나, 배포 빌드(`tauri build`)를 실제로 시도해본 뒤 복잡도를 다시 판단.
- **방법 B (Letta 연동)**: 파일 기반 페르소나로는 부족하다고 느껴질 때, 로컬 Letta 서버를 메타 에이전트로 붙여 상태 기반 메모리로 확장.
- **페르소나 내용 범위 확장**: 말투를 넘어 코드 스타일 선호, 반복되는 실수 패턴 등도 기록.

## 요청사항

위 스펙대로 구현을 진행해줘. "열린 기술 질문"은 구현 시작 전에 먼저 답을 확인하고 방식을 정한 뒤 진행해줘. 스코프에 없는 결정이 필요하면 임의로 정하지 말고 먼저 물어봐줘.
