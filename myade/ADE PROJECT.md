# 개인 ADE(Agentic Development Environment) MVP 구축 요청

> **진행 상황**: 아래 스펙(1단계, MVP)은 완료되었다. 완료 기준 체크리스트도 모두 충족된 상태다. 이후 진행 상황(2단계 GUI 셸 등)은 [`README.md`](./README.md)에서 관리한다.

## 배경

나는 현재 CMD/터미널 창을 프로젝트 폴더에서 직접 열고 `claude`(Claude Code)를 실행해서 쓰고 있다. 여러 창을 띄워도 각 Claude 세션은 서로의 존재를 전혀 모른다. 이걸 개선해서, Claude Code가 "다른 세션이 지금 뭘 하고 있는지"를 스스로 조회할 수 있는 최소 구조를 만들고 싶다.

설계 방향: "엔진 / 워크스페이스 / 오케스트레이션" 3층 구조로 나누고, pane 제어를 MCP 도구로 노출한다.

## 이번 단계의 목표 (MVP)

기존 터미널은 전혀 건드리지 않고, **로컬 MCP 서버 하나**를 새로 만들어서 Claude Code에 연결한다. 이 서버는 "지금 몇 개의 Claude 세션이 떠 있고 각각 뭘 하고 있는지"를 기억하고, Claude가 도구로 그 정보를 조회할 수 있게 한다.

## 명시적으로 하지 않을 것 (스코프 아웃)

다음은 이번 단계에서 절대 만들지 않는다. 나중에 별도 단계로 진행할 것들이다.

- 터미널 렌더러, PTY, GPU 렌더링 — 기존 터미널(Windows Terminal 등)을 그대로 사용한다.
- Codex 등 Claude Code 이외의 에이전트 CLI 지원 — 이번 단계는 Claude Code 전용.
- pane 간 에이전트 자동 협업/핸드오프 로직.
- git worktree 자동 관리.
- 시각화 UI(대시보드, GUI) — 이번 단계는 Claude가 텍스트로 상태를 조회할 수 있는 것까지만.

## 기술 스택 (확정)

- **런타임**: Node.js
- **MCP 서버**: Anthropic 공식 `@modelcontextprotocol/sdk` (TypeScript)
- **트랜스포트**: 로컬 stdio 또는 HTTP (구현 편한 쪽 선택, 단 Claude Code의 `.mcp.json` / `claude mcp add`로 연결 가능해야 함)
- **상태 저장**: 서버 프로세스 내 메모리 객체 또는 단순 JSON 파일. 데이터베이스(SQLite 등) 불필요.
- **세션 등록**: `claude`를 직접 실행하는 대신, 얇은 실행 스크립트(예: `myade.bat` 또는 `myade.sh`)를 만들어 실행 시 세션 ID를 발급하고 로컬 MCP 서버에 "세션 시작"을 알린다.
- **상태 보고**: Claude Code의 `SessionStart` / `Stop` / `Notification` 훅(hooks)을 설정해서, 작업 시작/종료 시 로컬 서버에 짧은 HTTP 요청(curl 등)을 보내 상태를 갱신한다. 터미널 화면을 파싱하지 않는다.

## 필요한 MCP 도구 (최소 2~3개)

1. `pane_list` — 현재 등록된 세션 목록을 반환 (세션 ID, 작업 디렉토리, 상태)
2. `pane_status` — 특정 세션 ID의 현재 상태(대기중/작업중/완료 등)를 반환
3. (선택) `pane_ping` — 서버가 살아있는지 확인용 헬스체크 도구. 1번 구현 전 연결 테스트용으로 먼저 만들어도 됨.

## 완료 기준 (Acceptance Criteria)

- [x] MCP 서버가 로컬에서 실행되고 Claude Code 설정에 정상 연결됨을 확인했다.
- [x] 실행 스크립트로 Claude Code를 켜면 세션이 서버에 등록된다.
- [x] Claude Code hooks가 세션 시작/종료 시 서버 상태를 갱신한다.
- [x] 터미널 창을 2개 이상 띄운 상태에서, 한쪽 Claude 세션에게 "다른 세션 상태 확인해줘"라고 물으면 `pane_list`/`pane_status` 도구를 호출해서 정확한 답을 준다.
- [x] 코드는 이후 도구를 추가하거나 시각화 레이어를 얹기 쉽도록 상태 조회/갱신 로직과 MCP 도구 정의가 분리되어 있다.

## 요청사항

위 스펙대로 처음부터 구현을 진행해줘. 진행하면서 각 단계(서버 뼈대 → 세션 등록 → hooks 연동 → 도구 구현 → 테스트)마다 무엇을 만들고 있는지 짧게 설명하면서 진행해줘. 막히거나 스펙에 없는 결정이 필요하면 임의로 정하지 말고 나에게 먼저 물어봐줘.
