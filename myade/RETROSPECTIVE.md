# myade 회고

기간: 2026-08 ~ 2026-09-14. 상태: 개발 중단.

## 하려던 것

바이브 코딩을 처음 접하고 시작한 프로젝트다. 공부를 시작하기 전에 책상부터 정리하듯, 코딩 에이전트로 일할 작업 환경부터 만들어 직접 쓰고 싶었다.

출발점은 작은 불편이었다. 터미널 창을 여러 개 열어 `claude`를 띄워도 "각 Claude 세션은 서로의 존재를 전혀 모른다"([ADE PROJECT.md](ADE%20PROJECT.md)). 그래서 세션들이 서로의 상태를 도구로 조회할 수 있는 로컬 서버부터 만들었다. 그 위에 멀티 에이전트 터미널 앱 같은 도구가 필요해 보였고, 캐릭터와 말투 기억(페르소나)을 붙여 세션과 대화하듯 일하는 환경까지 가 보려 했다.

## 페르소나에서 부딪힌 것

기록상 가장 많은 사고가 난 곳이다. 대부분 "기억이 엉뚱한 곳으로 새는 문제"와 "실패가 조용히 사라지는 문제"였다. 자세한 기록은 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)와 [AGENTS.md](AGENTS.md)에 있다.

- **기억이 새는 길이 여러 개였다.**
  - 한 캐릭터에게 한 역할극 지시가 전역 기억에 들어가, 다른 캐릭터가 그 캐릭터처럼 답했다. → 캐릭터별 파일로 나누고 전역 파일을 없앴다.
  - Claude Code의 자동 메모리가 저장소 단위라 두 번째 새는 길이 됐다. → 프로젝트에서 껐다.
  - 문서에 버그 예시로 적은 실제 캐릭터 이름을 에이전트가 읽고 자기 정체성을 거부했다. → 문서에는 "캐릭터 A/B"로만 쓰기로 했다.
- **실패가 조용히 사라졌다.**
  - 요약 서브프로세스가 엉뚱한 폴더에서 돌아 매번 "No conversation found"로 실패했다.
  - Windows의 PATH·인코딩 문제로도 조용히 죽었다.
  - 상속된 환경변수 하나 때문에 대화 기록 저장이 꺼져, 학습이 아무 흔적 없이 멈췄다.
  - → 실패하는 경로마다 stderr에 한 줄을 남기게 했다.
- **스스로를 다시 부르는 문제.** 요약용으로 포크한 세션도 훅을 보내 서버를 다시 불렀다. → 요약이 도는 동안 그 폴더의 이벤트를 무시하는 가드를 뒀다.
- **원본 대화를 망가뜨릴 위험.** `--fork-session`으로 항상 새 세션으로 분기했다. 서브프로세스를 강제로 죽여도 원본 파일의 해시가 그대로인지 직접 확인했다.
- **실사용 기록을 지운 사고.** 시험을 정리하다 사용자 데이터 폴더를 통째로 지웠다. → 저장소 밖 사용자 데이터는 확인 없이 지우지 않는다는 규칙이 생겼다.

## 그 밖의 사고와 교훈

- **SessionStart 훅만 http를 조용히 건너뛴다.** 디버그 로그로 찾아내 그 이벤트만 command 훅으로 우회했다. 문서에 없는 동작은 직접 확인해야 한다.
- **좀비 pane 132개, 유령 세션 109개.** 개발 중 앱을 재시작할 때마다 pane이 쌓였고, 끝난 세션이 끝난 것으로 기록되지 않았다. 1단계 조회 도구가 사실상 쓸모없어졌다. → 시간 기준 정리와 단일 종료 처리를 넣었다.
- **pane 닫기 버튼이 안 먹는 문제에 결함이 네 개 있었다.** 그중 하나만 고치고 "됐다"고 넘어갔다가 바로 다시 재현됐다. 이벤트가 소비되는지만 보지 말고, 애초에 발생하는지부터 확인해야 했다.
- **Windows에서 프롬프트를 인자로 넘기면 깨진다.** 이미 stdin으로 넘기던 코드가 있었는데 새 코드에서 그 패턴을 놓쳤다. → `claude`를 띄울 때는 기존 패턴을 그대로 따른다.
- **서명 안 된 빌드가 백신에 악성으로 잡혔다.** 배포하려면 서명부터 해야 한다.

## 버린 것

- **처음 GUI(왼쪽 터미널, 오른쪽 작업 계획 채팅과 승인 카드).** "실사용 패턴과 맞지 않아" 통째로 버리고 멀티 pane으로 갔다.
- **자체 GPU 렌더러.** 이 프로젝트의 차별점이 렌더링이 아니라고 보고 `xterm.js`로 갔다.
- **전역 페르소나 파일.** 캐릭터 사이 기억이 새서 없앴다.
- **pane 구성 자동 복원.** 지웠다. 이유는 기록에 없다.
- **에이전트끼리 자동 협업.** 실행 중인 세션에 메시지를 넣을 방법이 없어 미뤘다. 재개 때도 "수신·회수 시작 지시는 아직 필요하다"에서 멈췄다.

## 왜 멈췄나

문서에는 이유가 적혀 있지 않다. 아래는 작성자의 회고다.

- **CS 기초가 부족했고, 구조가 복잡했다.**
- **에이전트를 통제하지 못했다.** 개념을 모른 채 자연어로 이것저것 설명하다 보니, AI의 작업이 여러 갈래로 나뉘었고 그걸 종합하기 어려웠다. 규모가 내 역량으로 감당하기 어려울 만큼 순식간에 불어났다.
- **페르소나 관리가 어려웠다.** 위 사고 대부분이 여기서 났다.
- **터미널 앱까지 직접 만드는 건 너무 컸다.** PTY, Windows 특이사항, 창 관리에 시간이 들수록 원래 하려던 일에서 멀어졌다.
- **플랫폼에 비슷한 기능이 생겼다.** 서브에이전트, 세션 목록, 메모리 기능이 도구 안으로 들어왔다.

그래도 미련이 남아, 핵심인 "세션 간 요청"만 떼어 더 가벼운 [relay](../relay/RETROSPECTIVE.md)로 이어 갔다.

## 지금 다시 본다면

- 기능을 하나 더 붙이기 전에 구조와 완료 기준을 먼저 글로 정했어야 했다. 에이전트에게 맡길수록 이게 더 중요했다.
- "됐다"는 실제 동작으로 확인해야 했다. 위 사고 대부분이 확인을 건너뛴 자리에서 났다.
- 조용한 실패를 흔적으로 남기는 습관은 여기서 생겼고, 이후 프로젝트로 이어졌다.
