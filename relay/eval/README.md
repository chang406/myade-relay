# 교차 모델 검토 평가

이 디렉터리는 Relay와 **독립적**이다. `src/`를 변경하지 않고, Relay 서버도 필요 없다.

## 이게 답하려는 질문

`docs/PRD.md`의 「제품 판단 기록: 편의성 비교 (2026-09-23)」가 남긴 단 하나의 결정적 질문이다.

> 다른 벤더의 모델이 같은 벤더의 두 번째 패스보다 실제로 더 나은 검토자인가?

지금까지 이 프로젝트는 "다른 벤더는 학습 분포가 달라 실패 모드가 독립적이다"라는 논증을 써 왔다. 이는 **이론이며 측정된 적이 없다**. 결과에 따라 방향이 갈린다.

- **C가 B보다 유의하게 낫다** → 교차 벤더 연결의 가치가 데이터로 성립한다. 축소 스코프 재개의 근거가 된다.
- **C와 B가 비슷하다** → 두 번째 검토자의 벤더는 중요하지 않다. 가장 싼 경로가 이기고, 폐기 판단의 근거가 된다.

## 조건

| 조건 | 구성 | 의미 |
|---|---|---|
| A | Claude 1회 | 기준선 |
| B | A + Claude 독립 2차 패스 | 같은 벤더 두 번째 검토자 (fork에 해당) |
| C | A + Codex 독립 2차 패스 | 교차 벤더 두 번째 검토자 |

B와 C는 **2차 검토자의 벤더만 다르다**. 그 외 프롬프트, diff, 1차 패스는 동일하므로 비교가 질문을 정확히 겨냥한다. 각 패스는 맥락을 공유하지 않는 새 프로세스다. 독립적 검토자라는 전제가 그것이다.

프롬프트는 `prompt.mjs` 한 곳에 있고 두 벤더에 바이트 단위로 동일하게 전달된다. diff는 항상 stdin으로 보낸다(명령줄 길이 제한과 인용 문제 회피).

## 절차

### 1. 케이스 만들기

나중에 수정된 커밋이 라벨링하기 좋다. 수정 커밋이 곧 정답이다.

```powershell
git -C C:\path\to\repo log --oneline --grep="fix" -20
node eval/make-case.mjs --repo C:\path\to\repo --sha <버그를_넣은_커밋>
```

`eval/cases/<id>/diff.patch`와 `meta.json` 뼈대가 생긴다. **`meta.json`의 `defects[]`를 직접 채운다.** 이게 정답지이고, 비워 두면 그 케이스는 recall 신호에 기여하지 않는다.

케이스는 집중된 작은 커밋이 좋다. 큰 diff는 토큰만 쓰고 신호를 흐린다.

### 2. 실행

```powershell
node eval/run.mjs
```

케이스당 3회 모델 호출이 발생한다(실제 사용량이 소모된다). 결과는 `eval/results/`에 남고 Git에서 제외된다.

- `<case>/A.raw.txt`, `B2.raw.txt`, `C2.raw.txt` — 원본 출력
- `<case>/*.defects.txt` — 추출된 DEFECT 줄
- `runs.json` — exit code, 소요 시간, 토큰
- `scoring.json` — **사람이 채울 채점표**

### 3. 채점

`scoring.json`의 모든 항목에 `verdict`를 넣는다.

| verdict | 의미 | 추가 입력 |
|---|---|---|
| `tp` | `meta.json`의 라벨과 일치하는 진짜 결함 | `matchesDefectId`에 해당 id |
| `fp` | 실제 문제가 아님 | — |
| `extra` | 진짜 문제지만 라벨에 없던 것 | — |

**채점은 사람이 한다.** LLM judge를 쓰면 이 실험이 측정하려는 오류 상관 문제를 그대로 다시 끌어들인다.

### 4. 집계

```powershell
node eval/tally.mjs
```

`eval/results/report.md`에 조건별 recall, 오탐, 라벨 밖 실제 결함, 토큰, 소요 시간이 정리된다.

## 결과 해석 시 주의

- **표본이 작으면 작은 차이는 차이가 아니다.** 최소 10~15 케이스는 필요하다.
- B와 C 모두 A를 포함하므로 recall은 A 이상으로만 나온다. 볼 것은 **A 대비 증분**이다.
- `extra`(라벨 밖 실제 결함)는 recall에 안 들어가지만 중요한 신호다. 한쪽 벤더만 반복해서 잡아내는 종류가 있다면 그게 실패 모드 독립성의 증거다.
- 토큰 열은 Claude의 캐시 읽기를 입력에 합산해 Codex와 비교 가능하게 맞춘 값이다.

## 검증 상태

2026-09-23 기준.

- 합성 케이스 1개로 A/B2/C2 전 경로를 실제 Claude Code 2.1.219, Codex CLI 0.155.1에 대해 실행했다. 세 패스 모두 `exit 0`과 파싱된 DEFECT 줄을 반환했고, `tally.mjs`가 보고서를 생성했다.
- 출력 형식 파서는 `eval/parse.test.mjs`의 5개 테스트로 고정했다(`node --test eval/parse.test.mjs`). 벤더가 출력 형식을 바꾸면 조용히 0점이 되는 것이 가장 위험한 실패라 실제 출력 shape을 회귀 테스트로 남겼다.
- **실제 결함이 라벨링된 케이스로는 아직 실행하지 않았다.** 합성 1케이스 결과는 신호가 아니다.
