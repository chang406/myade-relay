# relay 회고

기간: 2026-09-14 ~ 2026-09-23. 상태: 일시 중단, 재개 보류.

## 하려던 것

[myade](../myade/RETROSPECTIVE.md)에서 핵심만 떼어 냈다. 코드를 옮긴 게 아니라 "세션 간 요청"이라는 생각만 가져와 처음부터 다시 짰다. 코드는 약 1,700줄로 myade의 절반 이하가 됐지만, 문서는 비슷하게 많았다(약 1,000줄). 캐릭터, 페르소나, 데스크톱 앱, 터미널 에뮬레이터는 처음부터 범위 밖으로 뒀다([README.md](README.md)). 패키지 이름(`myade-relay`)과 데이터 폴더(`~/.myade-relay`)에 그 흔적이 남아 있다.

풀려던 문제([docs/PRD.md](docs/PRD.md)):
- Claude Code와 Codex를 동시에 쓰다 보면, 한 세션이 다른 세션의 검토를 필요로 할 때가 있다.
- 그때 사람이 질문을 복사하고, 대상 창을 찾고, 답을 다시 옮겨야 한다.
- 이 왕복만 줄이되, 각 세션의 대화와 권한 확인은 그 터미널에 그대로 둔다.

## 설계에서 가장 신경 쓴 것

"단순 queue는 이 문제를 해결하지 못한다"([docs/PRD.md](docs/PRD.md)). 요청을 저장했거나 전송 명령이 성공한 것과, 상대 에이전트가 실제로 읽은 것은 다르다. 그래서 상태를 나눴다.

`queued` → `delivery_attempted` → `accepted` → `replied` → `delivered` (또는 `cancelled`)

- `delivery_attempted`는 전송이 성공했다는 뜻일 뿐이다. 상대가 읽었다는 뜻이 아니다.
- `accepted`는 상대가 직접 `relay_receive`를 불렀을 때만 된다.

그 밖의 원칙:
- 터미널에 키를 주입하지 않는다.
- 권한 확인을 자동 승인하지 않는다.
- 상대가 보낸 내용은 지시가 아니라 작업 데이터로 다룬다.

## 실제로 확인한 것

실제 Claude Code 2.1.218과 Codex 0.154.0으로 확인했다. 따로 적은 항목은 예외다([docs/TECHNICAL_VALIDATION.md](docs/TECHNICAL_VALIDATION.md)).

- **이미 아는 Codex 대화로 왕복.** Claude가 "31+11"을 물었고, Codex가 `42`로 답했고, Claude가 회수해 `delivered`까지 갔다.
- **새 Codex 대화 자동 등록.** 화면이나 기록 파일을 읽지 않고 공식 `thread/started` 알림으로 대화 ID를 얻었다. 그 대화와도 왕복이 됐다.
- **복구.** 끊긴 Codex 요청의 재시도는 실제 CLI로 `accepted`까지 확인했다. 서버 재시작 뒤 복구는 CLI 없이 격리 실험으로 확인했다.
- **진단.** 실제 CLI를 상대로 `doctor`가 통과했다.
- **실제 실행에서만 보인 버그.** 서버가 CLI의 절대 경로를 몰라 `spawn codex ENOENT`가 두 번 났다. 실제 CLI로 돌려 보고서야 드러났다.
- **시험.** 16개 통과. 보관 시점(2026-11)에도 그대로 통과한다.

확인하지 못한 것:
- 끊긴 Claude 쪽 재시도
- 전송 성공과 기록 사이에 서버가 죽는 경우
- 동시 세션과 부하
- macOS·Linux 실제 실행

## 왜 멈췄나

기록된 판단이 있다([docs/PRD.md](docs/PRD.md), 2026-09-15 사용자 결정).

> 시작 목적은 에이전트 간 인계 기술 자체보다 사용자의 편의였다. … 기술 검증 성공을 제품 편의성 검증 성공으로 해석하지 않는다.

코드가 작동하지 않아서 멈춘 것이 아니다([docs/HANDOFF.md](docs/HANDOFF.md)). 9월 23일에 편의성을 따로 비교했고, 중단을 유지했다.

- **진입 비용.** 요청 한 건당 조작은 0회지만, 그 전에 서버 하나를 띄우고, 양쪽 CLI를 다시 시작하고, MCP 승인을 두 번 해야 한다. 이미 열린 대화에는 붙지 못한다.
- **실질 경쟁자.** 하위 에이전트가 아니라 `codex exec resume`이었다. 설정 없이 승인 한 번이면 교차 벤더 호출이 된다.
- **벤더 기능과 겹침.** 그사이 CLI가 올라가면서 세션 목록(`claude agents --json`), 공유 데몬(`codex remote-control`), 이름으로 대화 찾기가 도구 안에 생겼다. relay에 고유하게 남는 것은 수신 증명 상태 설계와, Claude 세션으로 메시지를 넣는 경로뿐이었다. 그 경로마저 비공식 플래그에 기대고 있었다.
- **남은 질문.** 재개 여부를 정할 질문이 하나 남았다. "다른 벤더 모델이 같은 벤더의 두 번째 검토보다 실제로 더 나은 검토자인가." 이를 재려고 [eval/](eval/README.md)을 만들었다. 합성 사례 하나로만 돌렸고, 결함이 표시된 실제 사례로는 돌리지 않았다. 그래서 결론이 없다.

## 지금 다시 본다면

- 기술 검증과 사용 가치 검증을 따로 적은 것이 이 프로젝트에서 가장 잘한 일이다. 동작한다고 계속할 이유가 되지는 않았다.
- 진입 비용을 먼저 쟀어야 했다. 한 건당 편해도 시작이 무거우면 쓰지 않게 된다.
- 다음 프로젝트([baton](https://github.com/chang406/baton))는 그래서 서버를 아예 없앴다. 같은 시간에 두 세션을 잇는 대신, 다른 시간에 이어받는 문제를 파일과 Git으로 풀었다.
